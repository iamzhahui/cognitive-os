### 案例 001：A+B 迭代中的个人兜底与团队协作失控

- **日期**：2026-07-10 ~ 2026-07-23
- **作用域**：团队交付问题
- **事件分类**：系统问题 + 执行问题
- **核心问题**：团队没有建立"成员独立理解、独立交付、独立暴露风险"的机制，导致交付系统退化成A个人兜底
- **分析路径**：Case Lab + Thinking OS 七层 + 团队交付分析扩展
- **详细复盘**：[references/case-001-ab-iteration.md](case-001-ab-iteration.md)

**关键认知资产**：
- Trigger：当你发现自己同时承担开发、答疑、联调、兜底和风险上报，且忘记同步风险时
- 反模式：英雄式兜底——通过接管别人工作换取短期进度，制造长期依赖
- 长期原则：如果结果由你承担但过程不由你控制，你要么争取过程控制权，要么只承担局部责任

**6个认知偏差**：
1. 基本归因偏差（把BC问题归为"没听懂"而非"流程没验证理解"）
2. 计划谬误（估时忽略答疑、联调、返工、新人成本）
3. 英雄式兜底偏差（"我先顶上项目不会失控"→固化依赖）
4. 准备过度偏差（用文档完善降低不确定性，但团队协作风险无法靠文档消除）
5. 责任过载偏差（内化"项目成功=我保证每个人能交付"）
6. 传递完成=接收完成（"我讲过"="对方理解了"）

**推荐模型/书**：《Team Topologies》《目标》《无畏组织》《系统之美》
**推荐社会案例**：Toyota Andon、NASA哥伦比亚号、Google Project Aristotle、Amazon Working Backwards
