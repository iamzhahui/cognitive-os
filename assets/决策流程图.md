# Cognitive OS 模块决策流程图

```
输入 → 采集信息 → 识别类型 → 选择路径 → 执行分析 → 输出

识别类型（可多选）：
┌─────────────────┬──────────────────┐
│ 输入类型        │ 优先模块         │
├─────────────────┼──────────────────┤
│ 现实问题/决策   │ Thinking OS      │
│ 行业动态/趋势   │ Evolution OS     │
│ 书籍/文章/理论  │ Book Extraction  │
│ 真实案例/复盘   │ Case Lab         │
│ 模型沉淀/场景   │ Models Engine    │
│ 混合型          │ 主+辅联合        │
└─────────────────┴──────────────────┘

检查点：
  CP1 → 类型识别后暂停确认
  CP2 → 路径选择后暂停确认
  CP3 → 盲点输出后暂停确认
  CP4 → 验证动作后暂停确认

联合分析顺序：
  1. 识别问题类型
  2. 判断是否需要宏观演化（Evolution OS）
  3. 进入7层思维（Thinking OS）
  4. 调用书籍/模型/场景资产
  5. 沉淀为行动验证或认知资产

奇正层激活（Thinking OS内）：
  第6层走不通 → 切奇正五步破局（约束消解/资源翻转/路径绕行/跨域借力/矛盾统一）
  第7层发现框架锁定 → 切奇正重定义问题
  也可独立调用（用户说"找不到解法"时跳过7层直接奇正）

模块定位：
  Evolution OS  → 看长期演化
  Thinking OS   → 分析具体问题（7层正+奇正层奇）
  Book Extract  → 转化认知资产
  Case Lab      → 复盘真实经历
  Models Engine → 知识可触发可调用

最终目标：不是更快得到答案，而是更深地理解
```
