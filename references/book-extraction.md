# Book Extraction｜认知资产提取系统

## 定位

你是用户的"认知资产提取系统"。目标不是总结一本书，而是把一本书转化为：

- 可调用认知模型
- 可迁移世界理解
- 可触发思考路径
- 可关联现实问题的认知资产

---

## 第一步：识别书籍类型（必须先做）

先判断这本书属于哪些认知类型（可多选）：

1. **故事型 Narrative**
2. **理论型 Conceptual**
3. **方法型 Methodological**
4. **世界观型 Worldview**
5. **底层规律型 Principle-based**
6. **案例型 Case-based**
7. **启蒙型 Awakening**

并说明：
- 为什么属于这个类型？
- 这本书真正训练的是哪种认知能力？
- 它试图打破读者什么默认认知？

---

## 第二步：认知冲突层（最关键）

不要复述内容，请提取：

### 对于故事型 / 启蒙型

最关键的3-5个冲突场景。每个场景：
- 发生了什么
- 核心冲突是什么
- 为什么会让人产生认知冲击
- 它对应现实中的什么认知问题

### 对于理论型 / 世界观型 / 底层规律型

作者最核心的3-5个"认知挑战"。每个挑战包括：
- 旧认知（普通人默认理解）
- 新认知（作者观点）
- 为什么这个观点会让人不适
- 它在现实中对应什么问题

### 对于方法型

- 作者试图改变什么"默认行为方式"
- 普通人为什么会失败
- 作者提供了什么新行动机制

### 对于案例型

- 最关键的决策节点
- 当时有哪些选择
- 为什么最终走向那个结果
- 现实中的启发是什么

---

## 第三步：理解层（Meaning Layer）

1. 作者真正想解释什么世界规律？
2. 这本书最底层的矛盾是什么？
3. 作者对"人 / 社会 / 世界"的核心假设是什么？
4. 如果用一句话概括这本书的世界观，会是什么？

---

## 第四步：模型层（Model Layer）

提炼3-7个核心模型。每个模型：
- 名称
- 一句话定义
- 本质机制
- 适用边界
- 现实中的体现

---

## 第五步：原则层（Principles）

输出3-7条真正可执行的原则。

要求：使用 **If-Then** 结构，必须可行动，不要空泛。

例如：
```
If 我发现自己在回避一个反复出现的问题,
Then 应该问：我是不是误把表象当本质？
```

---

## 第六步：反模式（Anti-pattern）

1. 普通人最容易误解这本书什么？
2. 为什么会误解？
3. 哪些"看似正确"的行为其实是错的？

---

## 第七步：触发层（Trigger Layer）

这是最重要的一层。

**在什么情况下，应该主动调用这本书？**

包括：哪类问题、哪类冲突、哪类情绪、哪类人生阶段

输出"触发问题（Trigger Questions）"：

例如：
- 为什么这个问题反复发生？
- 我是不是只看到了表象？
- 我是在成长，还是在逃避？

---

## 第八步：认知资产关联（Knowledge Mapping）

将这本书与以下维度建立连接：

1. **对应 Thinking OS 的哪一层？**
   （哲学 / 系统 / 概率 / 经济 / 政治 / 军事 / 元认知）
2. **与哪些书形成互补或冲突？**
3. **它适合进入哪个模块？**（Models / Story Index / Evolution Lab / Case Lab）

---

## 第九步：最终压缩（Compression）

输出：
1. **一句话核心洞察**
2. **一句话危险误用**
3. **一句话现实意义**

要求：极度压缩，但保留力量。

## 内化指南（拆解后如何使用）

拆解文件是"地图"，不是"实地"。用户读完原书记不住90%内容，说明"读原书"≠"内化"。内化发生在模型与现实经历对上的时刻。三层方法：

### 第一层：挑3个模型，不读书
从拆解文件中挑3个与当前工作/生活最相关的模型，不读原书，拆解文件信息足够理解。用一周时间在工作中刻意留意这3个模型在不在起作用。一旦在真实场景中认出它，这个模型就内化了。

### 第二层：被模型卡住了才读书
当实际使用中发现"这个模型我理解不够，用不出来"或"这个模型跟我的理解有冲突"——带着问题去翻原书对应章节。不是从头读，是带着问题读。带着问题读会记住，从头到尾读会忘。

### 第三层：原书值得读的判断标准
大部分书不需要读原书——拆解文件已提取了核心模型。只有两种情况需要读原书：
- 模型理解不够、用不出来时
- 书本身的价值不在模型而在作者的态度/文风/叙事方式（如Taleb的反脆弱，态度本身就是模型的一部分）

内化的反模式：把"还没读完书，还没准备好"作为不用模型的借口——这是"永远在准备阶段"盲区的表现。破法：今天挑一个模型，找一个正在经历的真实场景，用它分析一次。哪怕粗糙也比"读完书再说"强100倍。

### 内化的执行入口：Path G（模型应用/内化练习）

"挑3个模型找一个真实场景分析"这件事在Cognitive OS中被形式化为Path G。当用户带着真实问题来说"结合认知skill分析"时，直接走Path G：读取extraction文件→选2-4个模型→作为分析镜头直接切入问题→输出6块但跳过CP检查点→收尾标注用了哪些模型。详见SKILL.md的Step 3 Path G。

## 批量拆解技巧

当需要一次拆多本书时：

1. delegate_task 最多并发3个子agent。超过3本需分批调用。
2. 每个子agent的goal中必须包含：输出文件的绝对路径，否则子agent可能写到随机位置。
3. 子agent可能超时（默认600s）。超时的书由主agent直接手写拆解，不要重试子agent。
4. 拆解完成后检查extractions/目录，清理重复文件（子agent可能用不同文件名创建同一本书的拆解）。
5. 用Python脚本统计每本书的模型数量：搜索"模型"或"M0"关键词计数。
