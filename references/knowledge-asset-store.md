# Knowledge Asset Store｜知识资产存储系统

## 定位

Cognitive OS的5个分析模块都能"提取"模型和案例，但提取完存哪里？怎么检索？怎么积累到100个？怎么验证够了？——本模块解决这些问题。

核心原则：**知识会忘，模型不会。模型比知识密度高。**

---

## 存储结构

知识资产存储在 `assets/` 目录下，分4个库：

```
assets/
├── model-library.md      # 模型库（最重要）
├── case-library.md       # 案例库
├── expression-library.md # 表达库
└── english-library.md    # 英语库
```

---

## 一、模型库（Model Library）

### 文件格式

每个模型按以下结构记录：

```markdown
### [模型名称]
- **分类**：系统/概率/经济/政治/军事/元认知/世界观/人性
- **一句话定义**：极度压缩，保留本质
- **本质机制**：为什么成立？因果结构是什么？
- **模型边界**：什么情况下成立？什么情况下失效？
- **模型信号**：现实中出现什么信号时应该意识到这个模型？
- **模型风险**：最危险的误用是什么？
- **现实映射**：职场/商业/社会/自我中的真实例子
- **联动模型**：通常和哪些模型一起出现？
- **触发问题**：什么时候应该主动调用？
- **来源**：哪本书/案例/经历提取
- **添加日期**：YYYY-MM-DD
- **使用次数**：0（每次实际使用时+1）
```

### 模型编号规则

按添加顺序编号：M001, M002, M003...
- M = Model
- 编号不回收，不重排

### 验收里程碑

| 里程碑 | 模型数量 | 能力表现 |
|--------|----------|----------|
| 一阶 | 50个 | 看到工作场景能说出哪个模型在起作用 |
| 二阶 | 80个 | 看到社会动态能说出演化到哪一层 |
| 三阶 | 100个+10个深度案例 | 看到决策情境能自动跳过表象直接到结构分析 |

### 使用计数机制

每次在实际分析中调用了某模型（无论是Thinking OS分析、Case Lab复盘还是日常问题分析），在该模型的"使用次数"字段+1。

定期检查：
- 使用次数=0的模型 → 需要找场景主动调用，否则遗忘
- 使用次数>5的模型 → 已内化，可降低主动调用频率
- 使用次数>10的模型 → 已成为"思维习惯"，可在模型库中标★

## 二、案例库（Case Library）

### 文件格式

每个案例按以下结构记录：

```markdown
### [案例名称]
- **编号**：C001, C002...
- **分类**：系统/权力/概率/执行/认知/资源/演化
- **事件**：发生了什么
- **背景**：相关上下文
- **我的判断**：当时怎么想的
- **我的思考过程**：从看到问题到做决定，中间的思考路径（不只记结论，记路径）
- **我的情绪**：当时情绪状态
- **最终结果**：结果是什么
- **7层复盘**：
  - 哲学：真正面对的问题是什么？是否误把表象当本质？
  - 系统：系统结构是什么？为什么反复出现？反馈回路？
  - 概率：是否过度确定？忽略黑天鹅？
  - 经济：真正投入和损失了什么？机会成本？
  - 政治：谁真正影响结果？谁获益谁受损？
  - 军事：行动路径是否合理？资源是否分散？
  - 元认知：被什么情绪驱动？是否在维护自我？
- **认知教训**：最核心的1条
- **关键判断**：哪个判断最关键
- **最该警惕的错误**：哪个错误最值得警惕
- **Trigger**：什么时候应该想起这个案例
- **反模式**：什么行为看似正确其实是错的
- **长期原则**：If-Then格式的可执行原则
- **来源**：真实经历/观察/新闻/书
- **添加日期**：YYYY-MM-DD
```

## 三、表达库（Expression Library）

### 文件格式

每天输出，按日期排列：

```markdown
### YYYY-MM-DD
- **今日事件**：一件事的简述
- **结构化表达**：用金字塔/SCQA等模式重构
- **30秒版本**：核心结论+1个关键原因
- **1分钟版本**：结论+3个原因+行动方向
- **表达模式**：用了哪个模式
- **今日金句**：一句话压缩
```

### 累积机制

- 每周回顾：哪个表达模式用得最多？
- 每月回顾：哪些表达模式已经成为"自动化"？
- 季度回顾：30秒表达是否比3个月前更连贯？

---

## 四、英语库（English Library）

### 文件格式

```markdown
### YYYY-MM-DD
- **中文骨架**：结构化表达的中文版
- **英语映射**：固定句式英语版
- **新句式**：今天新学的固定句式
- **口语录音**：是否完成（Y/N）
- **连贯度自评**：1-5分
```

### 固定句式积累

按场景积累，目标是20-30个固定句式覆盖大部分工作场景：

| 场景 | 中文骨架 | 英语固定化 |
|------|----------|------------|
| 表达观点 | 我认为核心问题是… | I think the core issue is... |
| 列举原因 | 原因有三点… | There are three reasons. |
| 因果递进 | 最终导致… | As a result... / This leads to... |
| 转折 | 但问题是… | The problem is... / However... |
| 行动建议 | 我建议… | I suggest / I recommend... |

## 检索机制

### 按场景检索

当遇到问题时，按以下路径检索已有资产：

1. 先看"触发问题"字段——有没有匹配的模型？
2. 再看Case Lab的Trigger字段——有没有类似案例？
3. 再看表达库——有没有类似场景的表达模板？

### 按Thinking OS层级检索

| 层级 | 对应模型分类 |
|------|-------------|
| 哲学思维 | 世界观型、底层规律型 |
| 系统思维 | 系统类 |
| 概率思维 | 概率类 |
| 经济思维 | 经济类 |
| 政治思维 | 政治类 |
| 军事思维 | 军事类 |
| 元认知 | 元认知类、人性类 |

## 与其他模块的关系

- **Book Extraction** 提取的模型 → 存入模型库
- **Book Extraction** 提取的表达模式 → 存入表达库
- **Case Lab** 的案例和沉淀 → 存入案例库
- **Models Engine** 的模型抽象结果 → 存入模型库
- **CognitionFlow** 的每日输出 → 存入表达库和英语库
- **Evolution OS** 的行业分析 → 可提取趋势类模型存入模型库

---

## 维护规则

1. **不删除**：即使模型使用次数=0，保留记录（可能未来场景会触发）
2. **定期盘点**：每月检查模型库，更新使用次数，标记★高频模型
3. **冲突标记**：如果两个模型矛盾，在两个模型中都标注"与M0xx冲突"，不强行统一
4. **来源追踪**：每个模型必须记录来源（书/案例/经历），便于回溯
